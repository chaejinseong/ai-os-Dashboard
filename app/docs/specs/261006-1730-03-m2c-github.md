## Goal

GitHub 연결 후 나에게 요청된 리뷰, 내가 연 PR, 나에게 할당된 이슈가 동기화되어
PIPELINE·BOARD·업무 화면에 잡히고, 1일 넘게 대기 중인 리뷰 요청과 기한 지난
이슈가 놓친 업무에 뜬다.

## Approach

**인증** — fine-grained PAT. 권한: Metadata(read), Pull requests(read),
Issues(read), 대상 저장소는 사용자가 고른다. Keychain `github.token`.
헤더: `Authorization: Bearer {token}`, `Accept: application/vnd.github+json`,
`X-GitHub-Api-Version: 2022-11-28`, `User-Agent: ai-os-dashboard`.
`save_github`는 `GET https://api.github.com/user`로 토큰을 확인하고 `login`을
settings에 저장한다.

**fetch** — `GET https://api.github.com/search/issues?q=...&per_page=50`, 쿼리 세 개:
1. `is:open is:pr archived:false review-requested:{login}` → 역할 reviewer
2. `is:open is:pr archived:false author:{login}` → 역할 author
3. `is:open is:issue archived:false assignee:{login}` → 이슈

reviewer PR마다 `GET /repos/{owner}/{repo}/issues/{number}/events?per_page=100`
에서 `event == "review_requested"`이고 `requested_reviewer.login == login`인
가장 최근 `created_at`을 `requested_at`으로 쓴다. 없으면 PR `created_at`.
reviewer PR은 최대 20개까지만 events를 조회한다. (fine-grained 토큰은 접근 가능한
저장소만 검색된다 — 연결 화면에 안내 문구로 보여준다.)

**변환** — 순수 함수 `fn search_item_to_item(json: &Value, role: Role, requested_at: Option<DateTime<Utc>>) -> Item`:
- PR: kind `PullRequest`, reviewer → stage `Review`, author → stage `InProgress`.
  같은 PR이 두 쿼리에 다 나오면 reviewer를 남긴다.
- 이슈: kind `Issue`, stage `Requested`, due = `milestone.due_on` (없으면 None)
- title = `title`, subtitle = 저장소 이름 (`repository_url`의 마지막 두 경로),
  url = `html_url`, timestamp = `updated_at`, done = false,
  id = `html_url`, meta = `{ role, requested_at, repo }`

**놓친 업무 규칙**
- `kind == PullRequest` && `role == reviewer` && `now - requested_at >= 1일` →
  reason "리뷰 요청 {N}일째", since = requested_at (기준 일수는 settings
  `github_review_days`, 기본 1)
- `kind == Issue` && `due < now` → reason "마일스톤 기한 {N}일 지남", since = due
